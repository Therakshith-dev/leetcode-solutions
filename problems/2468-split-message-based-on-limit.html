LeetCode 2468 — Split Message Based on Limit

Goal: split message into the fewest parts, each part has a suffix <a/b> and total length ≤ limit.

What the problem is really asking

Every part must look like: [some text] + <a/b> where:
  • b = total number of parts
  • a = part index (1 to b)
After removing suffixes and concatenating parts in order, you must get the original message.
Important constraint:
  • Each part (including suffix) must be length limit, except the last can be shorter.
  • You must produce as few parts as possible.
If a suffix itself is already too long (example: <100/100>) so that len(suffix) ≥ limit, then it is impossible for that b.

Main idea

We try different values of b (number of parts). For each candidate b, we compute:

TotalCapacity(b) = total number of message characters we can store across all parts, after reserving space for each part’s suffix.

If TotalCapacity(b) ≥ len(message), then b works. We return the first working b because that guarantees the fewest parts.

Key trick: avoid O(b) Group by digit length of a Compute capacity in blocks

Why the digit grouping matters

Suffix length depends on how many digits are in a and b.

Suffix: <a/b>
Length = digits(a) + digits(b) + 3
(the 3 comes from <, /, >)

digits(a) is:

  • 1 for 1..9
  • 2 for 10..99
  • 3 for 100..999
  • ...
If you loop a = 1..b for every candidate b, you’ll likely hit TLE on long messages.

The code avoids that by processing ranges of a with the same digit count in one shot.

Detailed walkthrough of your code

Step 1: loop over candidate b from 1 to n

We are trying to find the smallest number of parts. So we try b = 1, then 2, then 3, etc. The first valid b is optimal.

Step 2: compute len_b = digits(b)

len_b = len(str(b)) is the number of digits in b. This matters because every suffix contains b.

Step 3: compute TotalCapacity(b) using digit-blocks

Instead of iterating every a individually, we group a values that share the same digit length. That makes the inner loop run about O(log b) times, not O(b).

Inside the while a <= b loop:

  • digits = len(str(a)) — the digit count for the current block.
  • end = min(b, 10**digits - 1) — the last a in this block. Example: if digits = 2 then end is 99 (or b if b < 99).
  • count = end - a + 1 — how many a’s are in this block.
For that entire block, every suffix has the same length:
suffix_length = digits + len_b + 3
If suffix_length ≥ limit, then there is no space left for message characters. That b is impossible, so we break early.

Otherwise, each part in this block can store:

payload_per_part = limit - suffix_length
block_payload = count * payload_per_part

We accumulate that into total_capacity. Then jump to the next block: a = end + 1.

Step 4: if capacity is enough, build the answer

If total_capacity < n (message length), then b is too small — continue to next b.
If total_capacity ≥ n, we can split and return.

Building is straightforward:

  • For each part index a = 1..b, make suffix <a/b>
  • Capacity for this part = limit - len(suffix)
  • Take that many characters from message, append suffix
Notice: when a grows from 9 to 10, digits(a) increases, so suffix becomes longer and payload becomes smaller. Your build loop automatically handles that correctly.

Code (Python)

class Solution:
    def splitMessage(self, message: str, limit: int):
        n = len(message)

        for b in range(1, n + 1):
            len_b = len(str(b))
            total_capacity = 0

            a = 1
            while a <= b:
                digits = len(str(a))
                end = min(b, 10**digits - 1)
                count = end - a + 1

                suffix_length = digits + len_b + 3

                if suffix_length >= limit:
                    total_capacity = -1
                    break

                total_capacity += count * (limit - suffix_length)
                a = end + 1

            if total_capacity < n:
                continue

            result = []
            index = 0

            for a in range(1, b + 1):
                suffix = f"<{a}/{b}>"
                cap = limit - len(suffix)
                part = message[index:index + cap]
                index += cap
                result.append(part + suffix)

            return result

        return []

Complexity: checking each b is about O(log b) due to digit blocks. Building the answer is O(b). This is fast enough because we return as soon as we find the smallest valid b.
