LeetCode 1115 — Print FooBar Alternately

Problem Summary

Two threads share the same object:

  • Thread A calls foo()
  • Thread B calls bar()

We must print: 

foobarfoobarfoobar...

Exactly n times, strictly alternating.

Why This Is Hard

Threads execute independently and unpredictably.

Without synchronization: 

foofoofoobarbarbar
or
barfoofoobarfoo

The order becomes non-deterministic. We must enforce strict alternation.

Solution 1 — Using Condition Variable

import threading

class FooBar:
    def __init__(self, n):
        self.n = n
        self.turn = 0
        self.cv = threading.Condition()

    def foo(self, printFoo):
        for _ in range(self.n):
            with self.cv:
                while self.turn != 0:
                    self.cv.wait()
                printFoo()
                self.turn = 1
                self.cv.notify()

    def bar(self, printBar):
        for _ in range(self.n):
            with self.cv:
                while self.turn != 1:
                    self.cv.wait()
                printBar()
                self.turn = 0
                self.cv.notify()

Core Mechanism

turn = 0 → foo's turn turn = 1 → bar's turn

Each thread:

  • Waits until it's its turn
  • Prints
  • Switches turn
  • Notifies the other thread

Execution Timeline

Initial: turn = 0

Thread A: prints foo → turn = 1
Thread B: prints bar → turn = 0
Thread A: prints foo → turn = 1
Thread B: prints bar → turn = 0
...

Solution 2 — Using Semaphores

import threading

class FooBar:
    def __init__(self, n):
        self.n = n
        self.foo_sem = threading.Semaphore(1)
        self.bar_sem = threading.Semaphore(0)

    def foo(self, printFoo):
        for _ in range(self.n):
            self.foo_sem.acquire()
            printFoo()
            self.bar_sem.release()

    def bar(self, printBar):
        for _ in range(self.n):
            self.bar_sem.acquire()
            printBar()
            self.foo_sem.release()

Why This Is Elegant

  • foo starts with 1 permit
  • bar starts blocked
  • Each release unlocks the other thread
  • Perfect alternation

Visualization

foo_sem = 1
bar_sem = 0

foo acquires → prints → releases bar
bar acquires → prints → releases foo

Deadlock Consideration

Deadlock would occur if:

  • Both semaphores started at 0
  • Both threads waited forever

Correct initialization prevents this.

Performance

  • Time Complexity: O(n)
  • Space Complexity: O(1)

Each thread performs exactly n iterations.
